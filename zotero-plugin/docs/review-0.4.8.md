# ZotWatch 0.4.8（Codex 版）复审意见

对象：`zotwatch-0.4.8.zip`，仍然只有构建产物、没有源码。和 0.4.6 的安装包逐文件比较，逐条核对 `docs/review-0.4.6.md` 里的意见，并审查新增代码：`topic-scheduler.js`（自动检查）、`topic-insights.js`（阅读状态和覆盖统计），以及概览卡片和阅读标记。审查分三个方向（构建与接口、课题追踪、界面），每条结论和新问题都由另一个审查者独立复核过。行号指 0.4.8 安装包里的文件。

## 总评

- **这一版的进展集中在课题追踪和界面，修得认真：**
  - `<select>` 去掉了；
  - 关窗再开后，能看到并停止正在进行的检查；
  - 标题点一次不再打开两次；
  - 不填 Key 时不再卡死在翻页上；
  - 从调研创建课题不再把候选池当成新增，也不会重复创建；
  - 文库比对改成了查表；
  - 新增了自动检查、概览卡片、阅读状态和覆盖统计。
- **但上次三条「发布前必须处理」一条都没处理，构建问题还变严重了：**
  - 打包文件里手工粘贴的代码从 56 行增加到 80 行；
  - 所有窗口脚本加起来，未转义的非 ASCII 行从 303 行增加到 423 行（我们自己的构建是 0 行）；
  - 新增的两个脚本也没有源码。
- **新问题：**
  - 自动检查有一个高优先级缺陷：凡是「部分完成」的课题，会每 2 小时重查一次；
  - 后台检查会和用户手动操作抢同一份 OpenAlex 额度。
- **结论：** 0.4.8 仍然不能分发。功能层面可以作为 0.5.0 的原型，但必须先回到源码，按正常流程构建。

## 2. 新问题

### 2.1 凡是「部分完成」的课题，自动检查每 2 小时重查一次（高）

- **现象：** 只要不是完全成功，调度器就安排 2 小时后重试（`topic-scheduler.js:126、138–142`）。`retryMs` 从来没有配置，所以永远是最小值 2 小时，也不会逐次延长。可是很多「部分完成」再等也不会好，例如：
  - 某个种子在 OpenAlex 里找不到（每次都会重新解析）；
  - 新增达到上限；
  - 这次检查的请求预算用完；
  - 某个分支每次都失败。
- **后果：** 这些课题每 2 小时消耗一次请求预算，把每天 200 次的后台额度用在原地打转上；而且「上次成功时间」一直不更新。
- **修复：**
  - 只有暂时性错误（网络、429、5xx、冷却中）才短间隔重试，并逐次加倍：2、4、8 小时……最长到课题的检查间隔；
  - 「种子找不到 / 达到上限 / 预算用完 / 种子延后」都算本周期已完成；
  - 找不到的种子记下时间，约 30 天内不再解析。

### 2.2 后台检查和手动操作抢同一份 OpenAlex 额度（中）

- **现象：** 每天 200 次只是请求计数，有没有 Key 都一样。后台检查和推荐、调研共用同一个凭证池和限速器。
- **后果：** 后台检查一旦把 OpenAlex 的额度用完，凭证池会给 OpenAlex 设置持续到次日的冷却，所有功能都用不了 OpenAlex。不填 Key 时额度本来就很小，最容易出现这种情况。反过来，每日推荐或调研开始时，正在进行的课题检查也不会让路（`zotwatch.js:8359–8362`）。
- **修复：**
  - 每次预约请求前检查 OpenAlex 是否在冷却，以及已知的剩余额度是否低于预留值（例如这次预约的 2 倍），满足任一条件就跳过这一轮；
  - 不填 Key 时关闭自动检查，在开关旁写明原因；或者把每次限制在约 10 次请求、每轮 1 个课题；
  - 每日推荐或调研开始时，取消正在进行的课题检查。

### 2.3 其他（低）

- **自动检查的预算被限死在 50：** 课题设置的请求预算高于 50 时，自动检查仍按 50 算，因为索引摘要里没存 `requestLimit`（`topics.js:238–244`、`topic-scheduler.js:101`）。
- **「下次检查」三处显示不一致：** 课题列表的时间用「上次成功 + 间隔」计算，不考虑调度器的重试时间和全局开关；列表和详情在全局关闭或课题暂停时仍显示「定期检查已开启」；概览卡片是对的（`topics-ui.js:249、370`）。改为三处共用同一个文字函数，按概览卡片的规则。
- **概览卡片的错误处理：** 不显示单个课题的错误（读不到时「已收藏待读」显示 0，看起来像正常）；课题索引读不出来时，整个概览页加载失败（`overview.js:1100–1124`，`zotwatch.js:8765–8793`）。
- **概览卡片的跳转：** 「全部课题」和「查看课题」可能停在上次打开的课题详情，或者停在页面中部，看不到课题面板（`overview.js:1117`）。
- **推荐页变慢：** 推荐页每次刷新都要读整个文库（为了显示阅读状态），缓存 60 秒就过期（`zotwatch.js:8488、8700–8724`）。0.4.6 只读 `inbox.json`。应只对已加入文库的推荐按条目键查询。
