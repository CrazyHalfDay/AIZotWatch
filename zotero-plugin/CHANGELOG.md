# ZotWatch for Zotero 更新日志

发布新版本时，在这里新增一节 `## <版本号>`（与 `package.json` 的 `version` 一致）；发布流程会把这一节作为 GitHub Release 的说明。

## 0.4.0

新增「学术数据接口」：OpenAlex 与 Semantic Scholar 的 API Key、按服务自动限速，以及用 Semantic Scholar 补全摘要和 TLDR；关注期刊、关注作者和顶刊地学可以直接在 OpenAlex 中搜索添加，「从文库生成」改为先给出带学科和近似影响因子的期刊建议供挑选；新增「主题文献调研」：从关键词和种子文献出发扩展候选文献、AI 精读并写出带核对引用的中文综述。已安装 0.3.0 的用户会通过 Zotero 的插件更新自动收到此版本，原有设置全部保留。

### 功能

- 设置新增「学术数据接口」分区（紧跟「向量化」）：填写 OpenAlex API Key 和 Semantic Scholar API Key（默认隐藏，可点眼睛图标查看），Crossref 联系邮箱从「文献来源 → Crossref」移到这里（改名为「联系邮箱（Crossref 礼貌池）」，原有设置保留）。「测试接口」逐项检查 OpenAlex、Semantic Scholar 和 Crossref；OpenAlex 的「今日额度」显示最近一次请求时得知的当日剩余额度
- 自 2026 年 2 月起 OpenAlex 需要免费的 API Key：填写后，关注作者、摘要补全等所有 OpenAlex 请求都会带上它（不会出现在日志和错误信息中）。未填写时每天只有很少的免费额度，关注作者每次只获取第一页结果，结果被截断时运行问题中会提示「未配置 OpenAlex API Key：只获取了第一页结果…」
- 摘要补全新增 Semantic Scholar（填写 Key 后启用）：排在 OpenAlex 之后，每 500 个 DOI 一次批量查询；同时取回 Semantic Scholar 的 TLDR（一句话总结），没有摘要的推荐卡片会以一行灰色小字显示「TLDR：…」，有摘要时作为摘要的悬停提示。Key 无效时本次运行停用这一来源并提示
- 概览的「数据源」新增 OpenAlex（正常 / 未配置 Key / 出错，有额度信息时显示今日剩余额度）和 Semantic Scholar（已配置 / 未配置）两行；概览的「测试连接」也会检查这两个服务
- 关注期刊新增搜索框：按刊名或 ISSN 在 OpenAlex 中查找期刊（显示出版商、国家、ISSN、近似影响因子和发文量），「添加」为期刊的每个 ISSN 各写一行，学科和近似影响因子自动填写；支持 ↑ / ↓ / 回车 / Esc 键盘操作
- 「从文库生成」不再把 `library:14` 这样的占位内容直接写进列表，而是在分区内打开「期刊建议」：文库常见期刊经 OpenAlex 补全规范刊名、全部 ISSN、学科（OpenAlex 主题分类的子领域，如 `GEOCHEMISTRY_AND_PETROLOGY`）和近似影响因子（OpenAlex 两年均被引）；启用大模型时，还会用 Python 版 `zotwatch journals` 的提示词推荐文库中尚未出现的相关期刊，每个推荐都须在 OpenAlex 中找到同名期刊（找不到的丢弃），影响因子统一取 OpenAlex 的值。勾选后「加入所选」合并进列表（已有的行和注释保留，只补空缺），生成过程中可以取消
- 关注期刊新增「补全学科与影响因子」：为学科为空或为旧版 `library:N`、缺影响因子的行从 OpenAlex 补全，不覆盖已有的值；在中国出版的中文刊（含 *Acta … Sinica* 等拼音 / 拉丁刊名）学科加注 ` (CN)`，按中文核心期刊计分
- 关注作者新增搜索框：按姓名、ORCID 或 OpenAlex 作者 ID 在 OpenAlex 中查找作者（显示机构、论文数、被引次数、ORCID 和主要研究主题，便于区分同名作者），「关注」自动写入「姓名, ORCID」（没有 ORCID 时用 OpenAlex 作者 ID）；识别到的作者和无法识别的行逐行列出，可直接移除，原文本框收在「编辑文本」中
- 顶刊地学新增搜索框：在 OpenAlex 中搜索期刊并「添加」其全部 ISSN；顶刊列表按期刊名分组显示 ISSN（内置期刊和期刊列表中已有的刊名无需查询），可整体移除；ISSN 文本收在「编辑文本」中，仍可恢复默认
- 三个搜索框都使用 OpenAlex：未填写 API Key 时仍可搜索，但会在搜索框下方提示免费额度很小并链接到「学术数据接口」
- 主题文献调研（「调研」页）：输入主题、关键词和 / 或文库中的种子文献，选择深度（快速 / 标准 / 深度：候选池最多 150 / 400 / 1000 篇，精读 15 / 40 / 80 篇）、起始年份和数据源。插件在 OpenAlex 和 Semantic Scholar 中找到种子文献，沿它们的参考文献、施引文献和 Semantic Scholar 推荐，以及大模型生成的英文检索式在 OpenAlex、Semantic Scholar 和 Crossref 中检索，按 DOI 和相似标题去重（标出已在文库中的论文），按与主题和种子的相似度、与种子的关联、被引次数和新近程度排序，补全摘要和 TLDR；启用大模型时逐篇精读（研究问题、方法、数据、发现、贡献、局限和相关度，文库中有全文索引的论文还会读全文节选，精读结果跨调研缓存），按语义聚成 3–6 个主题，每个主题写一节，再写总述、争议、空白、未来方向和推荐阅读顺序。综述只能引用精读过的文献：不在提示中的引用编号被删除，没有有效引用的一节标注「（未引用文献，需核实）」。未启用大模型时给出按语义聚类分组的候选文献列表
- 调研的每一步完成后都会保存：取消、出错或关闭 Zotero 后可以「继续」；单个数据源、单篇精读或某一节失败时只记为问题，不中断调研。结果可「保存到 Zotero」（「ZotWatch 调研 · 主题」分类中的一篇笔记，含编号参考文献和 DOI 链接，并注明由 AI 生成；可同时把引用的或全部精读的文献放进该分类，已在文库中的条目直接加入，其余通过 DOI 导入；再次保存更新同一篇笔记）、「导出 Markdown」或「重新生成综述」；最近 30 项调研保存在数据目录中

### 改进

- 按服务自动限速：所有网络请求在发出前（包括重试）按目标服务排队，Crossref 每秒 3 次、OpenAlex 每秒 8 次、Semantic Scholar 每秒 1 次、arXiv 每 3 秒 1 次、Elsevier / Springer Nature 每秒 2 次，同时进行的请求数也有上限；后台运行和界面操作共用同一个限速器。服务返回 429（Semantic Scholar 还包括 5xx）并带有 Retry-After 时，同一服务的所有请求一起等待后再重试，Semantic Scholar 的重试间隔从 3 秒起。高级用户可在配置编辑器中用 `extensions.zotwatch.http.rateLimits`（JSON）调整
- 一个 DOI 被记为「各来源都没有摘要」后，新填 API Key 时只用新来源重新查询，不再重复查询已经确认没有的来源
- 期刊列表中学科以 `_CN` 结尾的期刊（如示例列表和 Python 版数据中的 `GEOSCIENCES_CN`）现在也按中文核心期刊计分，与 `(CN)` 相同
- 「清除缓存与推荐记录」同时删除调研记录和精读缓存（已保存到 Zotero 的调研笔记不受影响），确认提示中写明这一点；调研进行时不能清除

### 开发

- `src/survey/`：主题调研引擎，与 `src/engine.js` 一样不依赖 Zotero（HTTP、存储、文库、大模型和向量化都通过参数注入）；`test/survey.test.js` 用模拟的 OpenAlex、Semantic Scholar、Crossref、向量化和大模型覆盖完整流程、无大模型、取消后继续、失败隔离和引用核对，`test/addon.test.js` 在模拟的 Zotero 中测试文库搜索、选中条目、全文读取和保存到 Zotero
- `scripts/preview-survey-fixtures.mjs`：界面预览用的调研示例数据（一篇带编号引用的中文综述、候选文献、调研历史），`scripts/preview.mjs` 的模拟接口支持全部调研方法

## 0.2.0

移植 Python 版 AIZotWatch 的更多功能。已安装 0.1.0 的用户会通过 Zotero 的插件更新自动收到此版本。

### 功能

- 关注作者：在「设置 → ZotWatch → 关注作者」中每行填写一位作者（姓名 + ORCID，或 OpenAlex 作者 ID），每次运行通过 OpenAlex 查询他们最近 N 天（默认 60 天）发表的论文。这些论文不参与评分，只与文库去重，每篇只推荐一次；与个性推荐重合的论文不会重复出现，而是标注「关注：作者名」。相比 Python 版，首次开启不会拉取作者的全部历史论文，某次运行失败也不会漏掉论文，并跳过数据集、勘误等非论文条目
- 摘要补全增强：论文缺少摘要时，按 DOI 依次从 Crossref（预印本等非 Crossref 来源）、Elsevier、Springer Nature 和 OpenAlex 查找，取第一个不少于 80 个字符的摘要。Elsevier 和 Springer Nature 需在「设置 → 文献来源 → 摘要补全」中填写免费的 API Key，「测试连接」会检查 Key 是否有效。补全在关键词过滤之前进行（与 Python 版一致），关注作者的新论文同样会补全
- 摘要补全结果缓存在本地（`abstracts-cache.json`）：找到的摘要保留 30 天，各来源都确认没有的 7 天内不再查询（发表不到两周的新论文只隔约一天，等 OpenAlex 等收录）。与 Python 版不同，网络错误、限流和无法解析的响应不会被记为「没有摘要」，新填 API Key 后会重新查询；API Key 无效或某个来源连续出错时，本次运行停用该来源并在推荐窗口提示
- 顶刊地学速览：在「设置 → ZotWatch → 顶刊地学速览」中开启后，Nature、Science、PNAS、Nature Communications、Science Advances 等综合性顶刊（ISSN 可修改）单独抓取，不按文库相似度筛选，而是比较摘要与「地学领域描述」和各「排除领域」（大气、材料、化学、生物、天文、工程）的语义相似度，挑出固体地球科学与古生物文章；介于两可之间的灰区文章可交给大模型复核（未启用大模型时全部保留）。入选文章单独列为「顶刊地学速览」，每次最多保留最新发表的 30 篇，卡片显示与文库的相似度（仅供参考）和门控细节。顶刊使用单独的 Crossref 查询和抓取上限，不会挤占关注期刊的名额；阈值按向量化服务自动校准（API 模式沿用 Python 版的 0.30 / 0.22，本地模式 0.12 / 0.04；本地模式只比较字面词汇，开启大模型复核时除明显属于排除领域的文章外都交给大模型判断）。与 Python 版不同，大模型复核失败不会中断整次运行，而是保留该批文章并在推荐窗口提示
- 研究方向标签：启用大模型后，文库语义聚类得到的每个研究方向由大模型起一个简短的中文名称（依据每个方向最具代表性的标题和你的 Zotero 标签，使用 Python 版的批量提示词），推荐卡片显示「方向：…」，AI 摘要子笔记注明研究方向，设置页的「刷新状态」列出最大的几个方向；可在「设置 → AI 摘要与标题翻译」中关闭。与 Python 版不同，标签按方向成员沿用：文库增删论文、重新聚类（包括本地模式每次运行）都不会重新生成全部标签，只为新出现的方向补充；大模型回复格式不对时不保存，下次运行重试并在推荐窗口提示，而不是把「Cluster N」之类的占位名称永久保存
- 推荐窗口按来源分区显示（个性推荐 / 顶刊地学 / 关注作者），新增来源筛选；关注作者的论文显示「关注」标记，不显示分数，按发表时间从新到旧排列
- 后台提示和窗口标题分别列出各来源的新增篇数

### 改进

- AI 标题翻译覆盖本次所有新增论文；AI 摘要除个性推荐中分数最高的 N 篇外，顶刊地学和关注作者各另取最新的 N 篇
- 加入 Zotero 时，AI 摘要子笔记会注明推荐来源（推荐分数、关注作者等）；OpenAlex 中类型为预印本、书籍章节、书、报告和学位论文的关注作者论文分别保存为「预印本」「书籍章节」「图书」「报告」「学位论文」条目
- 设置页的「刷新状态」会列出识别到的关注作者和无法识别的行、顶刊地学速览的阈值和上次运行的入选情况，以及上次运行补全了多少篇摘要；运行问题按来源显示（如「关注作者（OpenAlex）」「摘要补全（Elsevier）」「大模型」）
- OpenAlex 返回异常数据时不再导致整次运行失败
- 读取文库条目的 Zotero 标签（用作研究方向的关键词，`ZotWatch` 输出标签和 ⭐、`/unread` 这类标记标签除外）；升级后第一次运行会重新聚类一次，向量缓存不受影响

## 0.1.0

首个版本：把 AIZotWatch 的文献推荐功能做成 Zotero 插件，支持 Zotero 7、8、9、10。

### 安装

下载下方的 `zotwatch-0.1.0.xpi`，在 Zotero 中打开「工具 → 插件」，点右上角齿轮选择「从文件安装插件…」。之后的版本会通过 Zotero 的插件更新自动推送。

### 功能

- 直接读取本地 Zotero 文库构建研究画像，增量向量化（只处理新增或修改过的条目），无需 Zotero API Key
- 每天自动从 Crossref（按关注期刊）、arXiv、EarthArXiv 抓取最新论文，摘要缺失时从 OpenAlex 补全
- 与 Python 版 AIZotWatch 一致的打分：k-NN 与语义聚类融合的相似度，加上期刊影响因子，按动态阈值分为「必读 / 推荐 / 一般」
- 推荐窗口（工具 → ZotWatch 文献推荐）：待查看 / 已加入 / 已忽略，支持筛选、排序和搜索；一键通过 DOI / arXiv 号加入 Zotero，放入指定分类并打标签
- 可选的 AI 功能：中文标题翻译、五要点结构化摘要（可保存为子笔记），支持任意 OpenAI 兼容接口（OpenRouter、DeepSeek、Kimi、通义千问等）
- 向量化服务：阿里云 DashScope、Voyage AI、OpenAI 兼容接口，或无需 API Key 的本地模式（默认）

### 快速上手

1. 在「Zotero 设置 → ZotWatch」中填写向量化服务的 API Key（推荐 DashScope），以及 Crossref 联系邮箱
2. 点「立即运行并查看推荐」。首次运行需要向量化整个文库，可能需要几分钟
